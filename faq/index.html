FAQ

The stuff I keep getting asked about the archive, what the numbers mean, and what the crawler actually saves.

What is SpicyChat Archive?

It's an independent public archive of SpicyChat characters. I repeatedly collect information that is publicly discoverable so older versions and bots that later disappear do not just vanish without any record.

It is not run by or affiliated with SpicyChat.

Why does Browse search more bots than the archive has saved?

Browse uses SpicyChat's live public Typesense index so you can search what SpicyChat is reporting right now. The archive total is the number of bots I've actually captured and stored so far.

Those are two different numbers. The result header intentionally shows the archive count instead of presenting SpicyChat's live match count like it was the archive total.

Why can the archive total be higher than SpicyChat's current public count?

Because this is an archive, not a mirror of only what is public right this second. Once a public bot has been captured, its historical record stays in the archive even if the bot later disappears, becomes unavailable, or is eventually confirmed deleted.

SpicyChat's public count is a live snapshot. The archive total is cumulative, so after enough history it can be higher than the live public index without anything being wrong.

Why don't archived + public + deleted bot counts always line up immediately?

The three numbers come from different evidence: the archive total is cumulative, the public number is SpicyChat's current public index count, and deleted only includes bots that passed the archive's deletion-confirmation rules.

The homepage now shows the remaining difference as not yet reconciled instead of hiding it. That bucket covers archived records that are not represented by the current public-index count but also have not been confirmed gone yet. It is separate from the smaller API verification queue.

Why is a bot missing from the archive?

The crawler is still working through a very large public catalog, so it may simply not have reached that bot yet. A bot can also become private or unavailable before the archive first sees it.

The archive is designed to keep filling those gaps over time rather than pretending it already has everything.

When does a bot count as deleted?

Disappearing from search is not enough. The archive only marks a previously seen public bot deleted after repeated explicit missing observations from SpicyChat's public character endpoint on separate checks.

That includes a real 404, and also the observed case where the endpoint returns HTTP 200 with an empty object while SpicyChat's frontend treats the bot as unavailable/404. One missing result only creates a suspect. A later check has to confirm it again.

Temporary request errors, 401/403 responses and other transient failures are not treated as deletion evidence.

Why can a crawler run add 0 bots and still be useful?

Finding brand-new IDs is only one part of maintenance. A run can also refresh richer character data, detect real creator edits, separate traffic-only metric changes, advance the long-term verification cursor, re-check possible missing bots and restore a bot if it becomes public again.

So a +0 discovery run can still do a lot of useful archive work.

What does a 50-page, 500-page or 1,000-page run actually mean?

That number is the budget for the rotating deep Typesense sweep, not the number of bots saved. A deep page currently contains up to 250 public search hits, so 500 pages can inspect up to about 125,000 listing hits.

The newest-bot overlap scan, ranking snapshots and character-API verification are separate parts of the same maintenance run. That is why the total work in a run can be much larger than the page number makes it sound.

How does the archive keep up with new bots while still checking old ones?

Each maintenance run checks the newest public pages first and stops once it has crossed a small all-known overlap window, so new bots are picked up quickly without rescanning the entire front of the index every time.

It also advances a rotating deep sweep through the public index and a separate resumable character-API verification cursor through stored bots. That gives newer bots fast coverage while older records still get revisited over time.

Does every little SpicyChat update create a new archived version?

No. The archive tries to keep meaningful bot changes, such as public name, title, greeting, scenario, creator, tags, visibility, avatar, definition visibility and similar character metadata.

Message counts, rankings, recommendation scores, SpicyChat's noisy updatedAt value and other backend/activity churn are not treated as proof that the creator edited the bot. The crawler tracks those separately from actual content changes where useful.

What's the difference between archive growth and SpicyChat public growth?

Archive growth means how many new records this project captured. During a backfill that number can be huge because the crawler is catching up on bots that already existed.

SpicyChat public growth is the net movement in SpicyChat's reported live public index over time. The Stats page keeps those separate so a big archive catch-up run is not presented like SpicyChat suddenly created hundreds of thousands of bots that day.

Are avatars saved permanently too?

Public avatar URLs are preserved with the bot record. Permanent R2 image copies are done gradually and are prioritized for useful cases such as changed or confirmed-deleted bots, so an archived image is not guaranteed for every active bot yet.

What does the × button on a bot card do?

It only hides that bot for you in that browser. The bot is not removed from the archive and nothing is sent back to the crawler.

You can restore individual bots, or restore everything, from the Hidden bots section in the filters.

Do my filters and hidden bots survive a reload?

Yes. Your include/exclude tags, match mode, filter-panel state and locally hidden bots are kept in your browser's local storage. Hard reloads do not reset them.

Clearing this site's browser storage will reset those local preferences.

What exactly gets archived?

The archive keeps public character metadata the crawler can actually observe: bot ID, name, title, creator, tags, public greeting, visible personality fields when SpicyChat exposes them, visibility/definition metadata, timestamps, public stats, avatar URLs, availability history and meaningful changes. Ranking/activity counters can be stored separately from creator-content changes.

It does not unlock hidden definitions or invent fields that SpicyChat did not expose.

Can I still view a bot after it is deleted?

If the archive captured it before it disappeared, yes: the deleted-bot page keeps the last public data the archive actually saw. A permanent avatar copy is only available when that image had already been archived; otherwise the old CDN image can eventually stop working.

The archive does not recreate private information or chats that were never part of the public bot record.

I'm a creator. Can I ask for an archived bot to be removed?

Yes. Send the bot ID or SpicyChat bot URL through the Archive channels in the QoL Discord, or open a GitHub issue for the archive. Include enough public information to identify the bot; do not post login/session data or other private account information.

Removal requests are reviewed manually so a same-name bot or unrelated creator's bot is not removed by mistake.

How do I report wrong archive data?

Send the bot ID/URL and what looks wrong in the Archive channels in the QoL Discord or in a GitHub issue. IDs matter more than names because different bots can have exactly the same name.

If the problem is a false deleted/unavailable flag, say whether the live profile still opens so the archived status can be rechecked against the character API.

Does the archive store private chats or account data?

No. The public archive is for public/discoverable character information. It does not need your SpicyChat password, cookies, auth/session tokens, private messages, private chats, persona data, Favorites/Later membership or local QoL settings.

Optional QoL Bot Status contributions are limited to saved bot snapshots intended for archive review; private account/session data should never be submitted.

Where is archive data stored?

The large bot records and archived media live in the project's Cloudflare R2 storage, while the public website keeps compact runtime/stat files in GitHub. The crawler has quota/storage guards so it can slow or pause expensive work before hitting configured limits.

The site only publishes archive data meant to be public. Local QoL recovery copies stay local unless you explicitly export or submit them.

How often does the archive update?

The normal crawler is scheduled every three hours, with quota and storage guards that can reduce or pause work when needed. Larger manual discovery batches are tested separately instead of silently changing the normal schedule.

The Stats page shows the latest completed batches and the current archive totals.

What happens if I submit Bot Status / Archive data from QoL?

Public QoL contributions are sanitized saved-bot snapshots only. They are not a direct write into the archive: a submission goes into a pending-review queue first, where it can be inspected as new, changed, duplicate, unavailable-history or problematic data before anything is approved.

The public submission flow does not need your chats, cookies, login/session tokens, personas, Favorites/Later membership or extension settings. It uses a random local install identifier/hash only to group submissions without turning that into an account identity.

A submitted “deleted” or “unavailable” status is only a warning for review. It cannot override the archive's own verification; current availability still has to be confirmed through the normal public character API checks.

Can I help with missing or older bot data?

Yes. Public historical bot links/IDs, old public snapshots and Bot Status / Archive exports can be useful for filling gaps. The Archive channels in the SpicyChat QoL Discord are the easiest place to discuss a contribution.
